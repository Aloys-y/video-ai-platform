# P6：直接展示片段分析结果

2026-09-07。用户确认不需要最终整局模型汇总，本轮以片段结果为最终产品输出。无需数据库迁移，新模式默认开关与白名单规则保持原有配置。

## 当前链路

```text
Kafka 父消费者 → 下载原视频 → FFmpeg 音轨 → ASR → 文本粗筛
→ 裁剪并上传片段 → RAG 检索一次并冻结参考
→ 有界线程池并行分析片段、保存结果 → CountDownLatch 等待
→ 全部成功后保存任务完成状态 → ACK
```

取消 `AudioPrefilterPipeline` 的最终 `text.summarize()` 调用。任务主记录只保存确定性的完成说明，不由模型生成整局结论；独立片段结果仍保存在 `analysis_segment.result`。普通片段失败后继续保存其他片段结果，父任务最终 FAILED；成功片段仍可查看。历史 SUMMARIZING 枚举与纯文本汇总辅助接口保留兼容，但当前粗筛主流程不会调用。

## RAG 与结果契约

- 首次冻结非空片段清单前调用现有 `RagOrchestrator`，不额外调用文本模型提炼参考。实际参考最多 12000 字符，用户关注点最多 10000 字符；用户问题超限明确拒绝。
- `SegmentGuidance(userPrompt, retrievalContext)` 与片段对象列表一起写入不可覆盖的 OSS 清单，schemaVersion=2。视频模型各段共用同一份参考，响应仍须基于各自画面。
- 重试复用片段清单时直接使用原参考，不重新检索；要用更新后的知识重新分析，应创建新任务。无音轨/无语音/零候选不检索 RAG、不调用视频模型。
- `SegmentModelSettings` 升级为 `p6-segments-v1`，完整执行快照会随之改变。旧 P4/P5 配置结果不直接作为新模型提示词结果复用；旧任务结果仍可查询，旧代次不被原地改写。
- 模型收到原有结构约束 + JSON 形式的用户问题/知识参考；参考不是画面证据，不能改变输出格式，不允许由攻略推断未观察到的事件。
- `SegmentReview` 新增 advice：证据起止时间、issue、suggestion、knowledgeBasis。每条建议必须包含在一个观察事件的证据区间内，时间从片段相对毫秒转换到原视频毫秒。允许没有建议，旧结果缺少 advice 时读为空列表。

## 查询与页面

- `GET /task/{taskId}`：校验当前用户归属，直接读数据库，避免进度或重试代次被旧缓存掩盖。
- `GET /task/{taskId}/segments`：返回当前代次、任务阶段、片段状态、成功数、原时间区间及结构化结果；不返回 OSS 对象键、原始响应或用量 JSON。
- `GET /task/{taskId}/segments/{segmentNo}/play?executionNo=N`：校验归属及当前代次，只为对应片段生成 1 小时播放 URL；不允许客户端传任意对象键。
- 详情页按原视频时间展示片段，包含画面观察、问题与建议、参考依据、不确定项。失败/取消任务也展示已保存结果；未开始的片段在父终态下显示“未执行”，而不是一直显示排队。
- 原视频起止时间作为片段标题下的轻量信息，观察/建议旁的时间用于定位。播放器在对应片段卡片内展开，可收起；宽屏与分析并排，窄屏位于分析上方。点击原视频时间后播放对应裁剪片段，播放偏移为 `原时间 - 片段起点`。轮询更新保留同任务同代次的播放器节点；离开页面或切换任务的迟到请求不覆盖新页面。
- 片段文本按纯文本转义，不执行模型返回的 HTML；零候选保留分析范围说明，不宣称整局没有交战。

## 验证与边界

`mvn test`：本轮最终统计见执行计划，日志 `logs/p6-segments-full-tests.log`。覆盖 RAG 先于片段调用且无汇总调用、参考冻结后重试不检索、问题变化拒绝混用、建议证据时间、失败任务成功结果查询、跨用户与跨代次播放拦截。原有 Latch、取消、迟到写入和内嵌 Kafka ACK 测试继续执行。

浏览器用本地模拟任务及 5 秒合成视频验证部分失败结果、时间按钮播放和零候选展示；未启动正式 API/Worker，未提交新的付费模型请求。真实录像中 RAG 是否改善建议质量、长片段输出长度及账户吞吐仍属于 P7。

前端转写/候选依据的原文查看不在本次片段展示范围；若需要可另增受权限保护的产物接口。本轮不实现整局汇总、跨片段事件合并或分层汇总。
