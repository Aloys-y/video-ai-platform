# 模型选型与粗筛成本对照（2026-09-10）

## 验证目标

使用 Qwen-Audio 3.0 Filetrans 转写、Qwen3.8-Flash 提取交战候选、Qwen3.7-Plus 分析视频，验证低成本预处理是否能减少高价视觉模型的无效输入。两个预处理阶段不等于固定两次请求：文本会按窗口分批。

样本为用户指定的 `D:/data/video/3.MP4`。这是单样本工程实验，不能代表所有长视频的准确率和节省比例。运行于隔离库，未切换线上配置。

## 比较口径

- 筛选方案：完整 ASR + 所有文本批次 + RAG + 所有视频片段调用。
- 原计划通过现有 SDK 做两组带同等知识参考的对照，但两次视频调用均未成功。后续成功对照改用 OpenAI 兼容接口，两组均使用相同 `SegmentReviewParser.VIDEO_PROMPT`，不附加 RAG 或额外用户提示，2 FPS、temperature=0、关闭思考、max_tokens=4096。因此成功对照不包含 RAG 增强效果。
- 片段链路包含转码压缩，直接方案输入原文件，因此比较的是整套处理方案，不能把全部差异归因于时间筛选。
- 费用为厂商回执乘华北2标价，不等于账户实扣；未知用量不记成零。
- 不凭模型自己输出认定准确率。需人工标注交战区间，检查召回、误选、视觉事实错误和时间定位。

判断式：`总节省 = 整片视频费用 - 片段视频费用 - ASR费用 - 文本筛选费用`。双方共同 RAG 费用在差值中抵消。无语音交战、边打边沉默等片段可能被漏筛；漏掉有效内容带来的费用下降不应当作有效优化。

### 质量与接入结论

1. 抽帧可见前段交战，后段主要为大厅、菜单、插画和真人镜头；筛选方向合理，但未逐帧标注，不能给出交战召回率或保证无漏检。
2. Plus输出仍有事实错误。片段输出把两段比赛都描述为第二名，抽帧中却可见一段“捍卫者”胜利画面；整片输出也存在类似问题。不能宣称“贵模型解决了准确性”，也不能凭单样本证明质量不下降。
3. 两次现有DashScope SDK视频调用约121秒、120.6秒失败，整片明确HTTP400；配置的读取超时为300秒。原错误处理未保留厂商错误码，不能直接认定为本地超时或确认SDK根因。
4. 同一片段和整片通过OpenAI兼容接口分别返回HTTP200。试验支持兼容接口可行，尚不足以排除原接口的偶发服务/下载问题。已补充现有Provider的安全错误码和requestId保留及单元测试。
5. ASR和文本已通过真实任务链路；视频成功是隔离测试中的兼容接口调用，未自动写回失败子任务、未部署兼容Provider、未切换线上模型。因此“模型组合的成本试验可行”不等于“新组合已部署且完整任务验收成功”。

### 可用于介绍的表达

为避免高成本视觉模型对长视频中的非交战内容进行全量分析，先用语音转写和文本模型提取交战候选，再裁剪后交给较强视觉模型。单条约7.6分钟样本中，视觉输入Token减少约68%；计入转写和文本筛选后，成功路径模型标价费用下降约45%。该数值是单样本结果，包含转码与筛选的综合收益，仍需更多人工标注样本验证召回和分析质量。
