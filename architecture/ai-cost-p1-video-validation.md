# AI 费用账本：P1 视频接入与验证

日期：2026-09-10。

本轮接入 DashScope 视频片段分析与业务重试。ASR 和文本粗筛已接入；查询 RAG 与费用展示仍待完成。本次未调用付费模型，未迁移业务数据库，未部署或重启服务。

## 执行过程

1. 片段业务线程显式传递任务 ID、执行代次、VIDEO_ANALYSIS 和片段编号。
2. 每次进入模型调用，完成请求准备后生成新的 callId，登记独立价格快照，再发送请求。
3. 读取响应后先提取原始 usage 并收尾记账，然后解析 choices、保存业务响应及解析片段结果。
4. 429/5xx 继续由已有片段重试循环控制。每次重试产生新账本行，归属于同一个片段；记录包含失败调用。
5. 复用已保存响应不会进入模型调用，不新增账本行。账本收尾失败不会触发模型重调；网络超时仍为未知费用。

账本 SUCCEEDED 表示模型调用已返回成功响应，不保证片段 JSON 合格或内容正确。HTTP 错误响应也读取 usage，有用量就记费用，不默认免费。

## HTTP 重试边界修正

检查本地 DashScope SDK 2.22.15 的连接工厂后，确认它沿用 OkHttp 默认客户端配置，ConnectionOptions 不提供关闭自动重试的选项。单纯在 SDK call 外登记一次，不能严格对应底层发送次数。

因此保留 SDK 的 MultiModalConversationParam 请求序列化，改为受控的 OkHttp 发送：

- 原生接口仍为 `/api/v1/services/aigc/multimodal-generation/generation`。
- 模型配置、fps=2、max_tokens、temperature 和 enable_thinking 保持原值。
- 每次请求独立连接/读写/总调用超时，禁止连接故障自动重试和重定向。
- 使用 OneShotJsonBody，阻止客户端对付费 POST 的隐式重放；文本和 ASR 提交同步使用此请求体。
- 原来的无上下文 DashScope call 入口明确拒绝调用；门面改为携带上下文调用 callDetailed。

OneShotJsonBody 只是一个不可重放的 JSON 请求体，不负责业务执行或重试，没有引入通用模型执行器。

仍使用原生接口，本次没有切换到 OpenAI 兼容接口，也没有宣称此前 qwen3.7-plus 的原生接口兼容性问题已经解决。协议参数已通过模拟测试；真实厂商验收可与后续模型接入合并。

新增单次 HTTP 总调用超时及 1MiB 响应上限；超限或响应读取中断保留费用未知。SDK 原有本地文件上传预处理不再使用，生产链路传入的是 OSS 签名 URL。

## 验证范围

- Mock HTTP 检查原生请求路径、授权、模型、视频 URL、采样率和输出参数。
- 错误响应脱敏；503 携带 usage 仍记费，每次客户端调用只发送一次。
- 输出 choices 无效，但已经返回的 usage 仍保留。
- 登记失败不发送；收尾返回失败不丢弃成功响应；登记后取消记 NOT_SENT 并保留中断标志。
- 已有片段服务重试测试确认 3 次调用均携带相同的任务/执行代次/片段上下文。
- 隔离 MySQL + Mock HTTP：两个任务并发，其中一个 503 后重试，最终三条独立调用记录；任务和片段归属正确。
- 本地 HTTP 服务返回 `503 + Retry-After: 0`，验证请求体不可重放机制使服务器只收到一次 POST。

MySQL 测试模拟 qwen3.7-plus 用量：失败调用输入 100、输出 0 Token，费用 0.0002 元；成功调用输入 1000、输出 100 Token，费用 0.0028 元。重试任务合计 0.003 元，另一个任务为 0.0028 元。以上为模拟数据，不是新增付费请求或性能压测结果。
