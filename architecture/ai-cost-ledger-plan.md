# 视频分析链路费用管理方案（精简版）

日期：2026-09-10。状态：P0、P1与P2代码和阶段验证已完成；业务库已迁移，服务已部署，3.MP4真实链路成功。部署证据见[部署与真实验收](ai-cost-deployment-validation.md)。本版替代原详细方案，以本版范围为准。阶段记录见[P0实施与验证](ai-cost-p0-validation.md)、[P1文本接入验证](ai-cost-p1-text-validation.md)、[P1 ASR接入验证](ai-cost-p1-asr-validation.md)、[P1视频接入验证](ai-cost-p1-video-validation.md)、[P1 RAG接入验证](ai-cost-p1-rag-validation.md)、[P2接口与展示验证](ai-cost-p2-validation.md)。

## 1. 审视结论

统一记录调用的方向正确，但上一版对异常恢复、价格管理和组件分层设计过多。当前需要的是看清视频链路的模型花销，不需要另建计费平台。

最终结构：**一张明细表、一个记录服务、一个价格计算类、一个费用查询接口。** 子任务表管理执行和结果，明细表管理实际调用消耗，SQL负责汇总。

| 原设计 | 本版处理 | 理由 |
| --- | --- | --- |
| 每次真实调用一行 | 保留 | 子任务重试可能多次消费，最终结果不能代替调用明细 |
| 调用前登记、调用后补用量 | 保留 | 进程中断后仍能知道存在待核对的调用 |
| 专用OSS费用回执备份、补账命令 | 删除 | 增加第二存储和恢复链路，第一版允许异常费用待核对 |
| 调用状态、费用状态两套枚举 | 简化 | 调用状态加可空金额即可，未知原因用字段说明 |
| 历史价格生效区间、通用计价框架 | 删除 | 只维护当前模型价格，调用前保存配置快照 |
| Mapper外再套Repository | 删除 | 当前MyBatis Mapper足够 |
| 全平台管理、导出、历史查询功能 | 延后 | 先做好任务详情的当前执行和累计费用 |
| 父子任务冗余费用字段 | 不添加 | 直接聚合，避免维护多份金额 |
| 真实付费调用作为记账功能必选验收 | 取消 | 用已有真实回执和Mock HTTP验证，减少重复消费 |

## 2. 范围与口径

管理五个阶段：ASR、TEXT_SCREEN、VIDEO_ANALYSIS、RAG_EMBEDDING、RAG_RERANK。只包含视频分析触发的RAG查询，不把知识库入库费用摊到视频上。

展示“AI服务按普通标价估算的人民币费用”，不含OSS、FFmpeg、数据库成本，也不代表账户实扣。第一版不处理免费额度、活动、缓存折扣、批量计费或多币种。

- ASR使用厂商报告的计费秒数，其他阶段使用厂商报告的Token。
- 金额NULL表示未知，0表示有依据确认零费用，两者不能混用。
- 失败但有足够用量仍计算费用，HTTP错误本身不能证明免费。
- 本次执行按task_id + execution_no汇总，视频累计包含所有代次。
- 金额用BigDecimal和DECIMAL，完整精度汇总后再格式化展示。

当前用量分散在ASR/片段的MySQL字段和文本的OSS响应中；旧ai_call_log未接入主链路。因此仍需要统一明细表。现有产物引用和usage_json保留给结果恢复使用，费用接口只汇总新表，不能重复累加。

## 3. 表设计

重建现有ai_call_log，不新建其他费用表。实施时按下列字段生成DDL。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| call_id | CHAR(36)，主键 | 应用生成UUID，一次实际提交尝试一个ID |
| task_id | VARCHAR(64) | 视频任务归属 |
| execution_no | INT | 执行代次 |
| stage | VARCHAR(32) | 五种阶段之一 |
| subtask_no | INT | 音轨、文本批次或片段编号；RAG单次查询为0 |
| model | VARCHAR(128) | 请求使用的模型ID |
| request_id | VARCHAR(128)，可空 | 厂商请求ID |
| remote_task_id | VARCHAR(128)，可空 | ASR异步任务ID |
| status | VARCHAR(20) | 调用状态 |
| input_tokens、output_tokens | BIGINT，可空 | 归一化后的输入、输出用量 |
| audio_seconds | DECIMAL(18,3)，可空 | ASR计费秒数 |
| usage_json | JSON，可空 | 原始用量，包括厂商总数、缓存和视觉细分字段 |
| price_snapshot | JSON，可空 | 冻结的计价规则及供应商、地域、版本 |
| estimated_cost_cny | DECIMAL(20,10)，可空 | 标价估算 |
| cost_unknown_reason | VARCHAR(32)，可空 | MISSING_USAGE、MISSING_PRICE或INVALID_USAGE |
| error_code | VARCHAR(128)，可空 | 安全错误码，不存含签名URL的原始异常 |
| started_at、finished_at | DATETIME(3)，后者可空 | 开始、结束时间；可相减得到耗时 |

必要索引：主键call_id，以及(task_id, execution_no, stage, subtask_no)。第一版不添加面向未来统计的索引。

删掉重复或当前不需要的字段：自增id、user_id（通过task校验）、retry_no（按明细顺序展示）、单独price_version（快照已有）、单独total_tokens（原始usage已有）、endpoint_kind、专用费用响应OSS引用。

同一个call_id重复写入相同回执必须幂等；已有金额不能被空回执清掉，不同已知回执冲突时保留原值并报错。模型重试新建call_id，数据库写入重试沿用原call_id。task/代次/阶段归属登记后不可修改。

## 4. 一个状态字段足够

| status | 含义 |
| --- | --- |
| RUNNING | 已登记，正在发送或等待结果；ASR已提交也使用该状态 |
| SUCCEEDED | 模型响应成功，不代表业务解析成功 |
| FAILED | 收到明确错误响应 |
| UNKNOWN | 未取得确定结果，例如网络中断 |
| NOT_SENT | 登记后确认尚未发送就取消，金额为0 |

金额是否已知由estimated_cost_cny判断，不维护第二套费用状态机。成功响应缺usage，允许SUCCEEDED + NULL + MISSING_USAGE；错误响应带usage，允许FAILED + 已算金额。

进程强杀可能留下RUNNING行。查询时结合原执行是否仍有效，将失效执行的未完成行显示为“调用结果/费用待核对”。不增加后台扫描任务，也不推断远端已取消或免费。未来收到真实回执仍可补齐。

## 5. 调用流程

检查任务状态并取得并发许可 → begin登记RUNNING和价格快照 → 请求模型 → finish保存usage并计算金额 → 原有业务解析与结果保存。

调用前登记失败则不发送请求。登记提交结果不确定时，先按call_id核对，不另外生成ID绕过登记。登记后发送前确认取消，写NOT_SENT；崩溃则保守保留待核对。

HTTP调用期间不持有数据库事务。必须在业务解析前记录usage。Embedding/Rerank要在解析向量/排名之前记录，不能只在方法外根据返回或抛异常判断是否发生费用。

### ASR的唯一特殊处理

一次转写提交登记一行，取得远端ID后绑定到该call_id；轮询和下载结果不新增费用行。现有ASR流程持有该call_id，终态回执更新原行。

进程恢复如已有remote_task_id，通过任务、代次、part编号和远端ID找回原行，不重新登记同一远端任务累计费用。正常提交与绑定沿用现有子任务的执行约束；出现多行匹配时报告冲突，不任选一行。

ASR终态用量先记账，再下载或解析转写文件。没有远端ID的未知提交不能为补费用而重新提交。第一版不新增ASR费用恢复调度器。

### 记账故障

收到模型回执后，写库失败最多额外重试2次，只重试相同call_id的写入，不重调模型。达到上限后记录脱敏错误日志，允许已有响应继续进入业务处理；费用保留待核对。原业务能否保存成功仍遵循现有数据库错误处理。

不新建OSS费用备份、自动补偿或恢复命令。有需要时人工利用现有模型响应核对；响应也丢失就保留未知。日志用于排查，不作为另一套承诺可靠的账本。

**接受的边界：数据库故障或进程崩溃时，少量调用费用可能无法自动补齐。** 前置登记提供待核对线索，页面必须显示金额不完整。这是保持轻量的明确取舍，不承诺严格完整记账。

## 6. 价格计算保持具体

在现有配置中增加ai.pricing，只列当前接入的ASR、文本、视频及RAG模型。每项包含供应商、地域、模型ID、配置版本、计价单位和当前阶梯单价；不做价格管理页面、生效时间匹配引擎或热更新。

调用前复制该模型整条规则到price_snapshot，收到实际用量后选择档位。运行中使用冻结规则，之后改配置不改变旧金额。未知模型保存用量并标MISSING_PRICE，不套用其他模型单价；旧记录不自动按新价重算。

- Token费用 = (输入Token×输入单价 + 输出Token×输出单价) / 1,000,000。
- ASR费用 = 计费秒数×每秒单价。

AiCostCalculator用普通Java分支实现当前两种计价单位和输入阶梯，不做插件、策略注册中心或表达式引擎。供应商字段差异在对应客户端归一化。

视觉/思考Token若已包含在输入或输出，不再加一次；Embedding/Rerank的total_tokens只能按已确认的产品计量语义使用。未知usage格式保留原JSON并标INVALID_USAGE，不猜金额。

## 7. 最小代码结构

| 模块 | 组件 | 职责 |
| --- | --- | --- |
| video-common | AiCallContext、AiUsage | 简单record，明确任务和子任务归属及用量 |
| video-infrastructure | AiCallLogMapper | SQL登记、更新、聚合 |
| video-infrastructure | AiCallRecorder | begin、bindRemoteTask、finish，短事务及有限写库重试 |
| video-infrastructure | AiCostCalculator | 根据冻结价格计算金额 |
| video-worker / video-rag | 已有模型客户端 | 在实际网络调用边界接入Recorder |
| video-api | 已有TaskController、新增TaskCostService | 增加接口，复用TaskSegmentService归属校验，组织只读费用查询 |

不再套Repository、通用模型执行器，不新增Maven模块。Recorder放在infrastructure，供Worker和RAG共同使用。

上下文从视频任务显式传入片段工作闭包和RAG查询，普通ThreadLocal不会自动跨线程传播。现有ExternalUsageReceipt不作为线上唯一入口，也不能与Recorder对同一请求各记一行。

业务结果仍校验租约；**已登记调用的用量收尾只按call_id更新，不因租约失效拒绝记账**。失效执行只能完善自己的费用行，不能修改当前任务结果或别的调用。

## 8. 一个接口、一块页面

第一版接口：GET /api/task/{taskId}/costs。

先按当前用户校验任务归属，再返回当前执行费用、视频历次累计、阶段和当前片段汇总。P2进一步收敛：第一版不返回最近100条逐次调用明细，不引入hasMore或分页；调用明细仍完整保留在账本，页面先满足链路与片段费用查看。暂不增加历史筛选和全平台统计接口。

每组汇总返回已知金额、未完成/待核对数量和费用是否完整。金额用字符串传给前端。只聚合ai_call_log，不把多张子任务表JOIN后直接SUM，避免金额倍增。

新执行的config_snapshot保存costLedgerVersion=1，区分完整接入但无新调用与启用前缺少记录。标记不保存金额、不补写历史数据。查询在只读REPEATABLE_READ事务中读取任务、覆盖标记和账本；coverageKnown表示接入覆盖，complete还要求任务已终态且没有未收尾或未知费用的调用。

任务详情沿用现有轮询，展示：

- 本次AI费用：已知金额 + 待核对调用数量。
- 视频累计：包含历次失败和重试的已知金额 + 待核对数量。
- 阶段明细：ASR秒数，文本、RAG和视频的输入/输出Token与费用。
- 视频片段明细：每段Token、调用次数（包含重试）、费用。

复用结果不建新调用行，界面通过原有复用标记显示“本次新增费用0”，旧费用仍归原代次。未调用阶段、全量复用与启用前无记录的任务分别显示，不能仅凭无账本行认定费用为0。

第一版只对新验收任务承诺完整接入。旧测试任务不回填猜测费用，显示“无完整费用记录”。若实施时决定清理测试任务，按已有测试数据处理范围执行，不为旧数据加兼容层。普通用户接口不暴露原始usage、错误响应或存储凭据。

## 9. 实施与测试

| 阶段 | 工作 | 必须验证 |
| --- | --- | --- |
| P0 | 重建旧ai_call_log，实现Mapper、Recorder、Calculator | 金额精度、阶梯边界、幂等、NULL与0、未知模型/用量 |
| P1 | 接入ASR、文本、视频和查询RAG | 一次实际调用一行；ASR轮询不增行；重试新行；解析失败仍计费；并发不串账 |
| P2 | 费用接口与详情展示 | 当前/累计一致、失败和复用费用、待核对提示、用户越权、聚合不倍增 |

每阶段测试通过再继续。数据库行为用隔离MySQL验证，网络行为用Mock HTTP和已有真实usage回执验证；无需为开发账本重复付费调用模型。

故障测试覆盖必要边界：登记失败不请求模型，收尾失败不重调模型，失效执行可记费用不可写结果，进程中断留下待核对行。不扩展为完整补偿系统测试。

上线时先确认无在途测试任务，再备份重建旧ai_call_log。不同时更换模型和修改调度器；真实完整链路验收可与后续模型接入验收合并，避免重复消费。

## 10. 最终边界

保留：调用明细、价格快照、必要幂等、未知费用、当前与累计汇总。

不做：费用Outbox、专用OSS备份、补账调度器、历史价格引擎、多币种/优惠结算、全平台费用后台、父子任务费用缓存。

以后只有出现实际需求，例如未知费用频繁发生、查询性能不足或必须对齐账户账单，才针对该问题增加恢复、缓存或对账能力。
