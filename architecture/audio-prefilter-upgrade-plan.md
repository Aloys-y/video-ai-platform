# 语音粗筛与片段分析方案（讨论稿）

2026-09-07 更新。P0–P6 当前范围已实现，新模式默认关闭。最终输出为每个片段的分析结果，不再生成整局模型汇总。

## 处理流程

```text
原视频上传 OSS → 用户确认 → 任务表 + Outbox → Kafka
→ Worker 下载到临时磁盘 → FFmpeg 提取音轨 → 云端 ASR
→ 带时间戳的文字 → 文本模型筛选候选 → 合并、扩展、拆分时间区间
→ 裁剪并上传片段 → RAG 检索并冻结分析参考
→ 共享线程池分析各片段、分别保存结果
→ 父消费者等待完成 → 保存任务终态 → ACK
```

Java 调度 FFmpeg 独立进程，不将整条视频读入 JVM 内存。语音只提供候选线索，实际问题必须由片段画面支撑。没有语音线索不能证明没有交战。

## 片段分析与展示

- 首次为视频检索一次相关知识，与用户问题一起冻结在 OSS 片段清单。各片段共享参考；重试沿用原参考，避免混用不同知识版本。
- 视频模型返回片段分析、画面事件、带证据时间的问题与建议、参考依据、不确定项。参考是判断标准，不是本视频发生过的事实。
- 每段结果单独存 MySQL，音轨、转写、候选清单、裁剪视频和原始模型响应保存在 OSS。
- 前端按原视频时间展示片段。点击证据时间播放对应裁剪片段，失败/取消任务也可查看已保存结果。
- 不再做最终模型汇总、跨片段事件合并或分层汇总。父线程仍需判断所有片段是否成功，以确定任务状态。

## 并发与等待

- 每 Worker 共用独立的片段线程池：固定 4 线程，有界队列 16，都是待长片段压测的初值。父消费者不进入该线程池。
- 依次提交全部轻量片段工作，不设单视频滑动窗口；接受大任务先占队列、小任务等待更久的取舍。
- AbortPolicy 明确拒绝，队列满时父线程持续等待并重试当前片段，不设独立的 120 秒入队期限，不静默丢弃。
- 每任务用 CountDownLatch 等待完成，并定期检查取消、执行代次和线程池关闭。未提交/启动前取消需要计数；正在运行的片段实际退出后才计数。
- 整局默认从 PROCESSING 开始最多 30 分钟，包含媒体处理、ASR、粗筛、排队和视频分析；Kafka 未领取的等待不计入。Kafka max.poll.interval.ms 当前为 40 分钟；模型请求仍有单次超时。

## 失败与恢复

| 情况 | 当前行为 |
|---|---|
| 无音轨、无有效语音或零候选 | 显示范围说明，不调用视频模型，不编造分析 |
| 一个片段失败 | 其他片段继续处理，保存成功结果；全部收尾后整局 FAILED |
| 取消、整局到期、线程池关闭 | 停止提交、移除排队工作、尽力中断在途调用、隔离迟到写入 |
| 全部片段成功 | 保存确定性的完成说明和任务 COMPLETED，无最终模型调用 |
| 成功或失败状态可靠落库 | 父消费者 ACK |
| 无法可靠确认终态 | 不 ACK，交消费者错误处理核对 |
| 用户重试 | 新执行代次，按输入/配置/片段身份复用有效产物和成功结果 |

片段不独立发送 Kafka，不增加数据库领取队列、片段租约或自动续跑调度器。旧执行结果禁止覆盖新执行。视频 URL 和结果接口校验当前用户与执行代次。

## 2026-09-08：每视频最多5片段

新执行的分析上限设为5。候选仍全量粗筛并保存；经时间合并、上下文扩展、单片段时长拆分后，按时间顺序保留前5段。不是按重要性排序，不足5段不补齐；实际选中时长用于视频费用预算，原片转写费用仍按整段计入。每片段时长上限保持不变。历史结果不删减，配置快照变化后重试可能无法复用旧产物。
