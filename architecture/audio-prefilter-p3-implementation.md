# P3：文字粗筛与片段结果契约

2026-09-07。P3 服务已实现；Kafka 整局主流程仍在 P5 接入，本阶段不会提前 ACK 或把粗筛完成标记为整局成功。

## 核心调用

```text
P2 prepareTranscript → OSS 中带时间戳的转写
→ TextScreeningService.screen(taskId, executionNo)
→ CandidatePlanner 分窗口、校验证据ID、映射原片时间
→ 合并、前后扩展、裁边界、超长分段、预算检查
→ 候选清单存 OSS，绑定 analysis_execution.candidates_object_key
→ P2 prepareSegments(..., screening.ranges()) 裁剪并冻结视频片段
```

粗筛提示词保留用户确认过的 P0 原文，测试校验其 SHA256 与 `accepted-baseline.json` 一致。每窗最多80句，重叠10句；同时按UTF-8字节限制输入，超长单句明确失败而不是截断。合并间隔5秒，向前扩10秒、向后扩15秒，超过单段180秒时完整拆分。

`CandidatePlanner` 是纯计算组件。模型只提供句段ID、类型和理由；未知/跨窗口ID、模型自造时间戳、重复转写ID、越界区间均拒绝。相隔较远的证据分开映射，避免把模型合并的一组ID之间的大段空白全部纳入交战。零候选明确返回 `NO_CANDIDATES`，不等价于整局没有交战。

`TextScreeningService` 保存完整候选、最终区间、转写摘要、配置摘要、逐批原始响应引用及厂商usage。P2裁剪入口必须核对已冻结候选清单，不再接受未经粗筛冻结的任意区间。

## 模型调用与恢复

新增纯文本 `AiTextClient`，用百炼兼容接口调用 `qwen3-vl-flash`，不伪造视频URL。默认不重试、不跟随重定向，凭据仅发往百炼HTTPS接口。`TEXT_API_KEY` 为空时复用现有 DashScope 凭据。

新增 `analysis_text_call`，唯一键 `(task_id, execution_no, purpose, batch_no)`，只留调用记录，不领取任务：

- 请求前插入输入摘要；已有记录而无响应表示状态不明，不自动重提。
- 原始响应先上传OSS并绑定，然后检查完成标记、JSON和候选结构。格式失败抛 `InvalidTextResultException`，与网络调用失败分开。
- 有已保存响应时直接重新解析；同批输入摘要变化则拒绝覆盖。完整候选已保存时直接读取清单。
- 本代响应即使刚遇到父任务取消仍留存审计，后续候选绑定必须通过当前代次/PROCESSING校验。

当前只保证同一执行代次内复用文本响应；手动新代次会建立新调用记录，不宣称跨代自动复用。请求成功但响应尚未保存时发生进程退出，仍需要人工核对。

## 汇总和视频结果

新增 `SegmentReview`、`SegmentReviewParser` 和 `VIDEO_PROMPT`：视频结果应包含摘要、可观察事件、片段内证据时间及不确定项；解析时校验范围并映射到原片时间。P4调用视频模型时接入此契约，已有整片Provider返回格式本阶段不变。

`summarize(...)` 使用同一纯文本接口，核对冻结片段全部有结果，再按原片时间排序。知识库上下文由调用方传入，粗筛不调用RAG。汇总输入超限时明确要求分层汇总，不静默截掉部分片段；分层汇总不在本次实现范围内。

## 配置和费用边界

Worker YAML 新增 `analysis.text`，包括模型、窗口、提示词基线、响应上限和费用预估参数。有效配置进入 P2 创建的本代快照；已有 P2 旧快照不会被原地覆盖，应使用新执行代次。

单批输入预算30000字节（含预留开销），最大输出4096 tokens，最多64批、500个候选。候选数量/总时长继续受媒体配置限制。调用文本模型前预留全部粗筛和一次最大汇总用量，裁剪前加入视频时长费用预留；超过整局预估预算10元时失败，不删除候选凑预算。

费用是工程预估：文本默认按输入0.15元/百万tokens、输出1.5元/百万tokens，参考[百炼价格](https://help.aliyun.com/zh/model-studio/model-pricing)的相应模型及输入档位；ASR按全音轨保守估算。视频阶段0.20元/分钟是工程预留，**不是厂商报价**，需在P4按实际视频模型校准。未包含存储与流量，不代表实际账单或平台硬扣费上限；更换模型/地域时必须更新单价配置。模型别名可能更新，版本可复现性还需生产配置使用已验证的固定模型ID。
