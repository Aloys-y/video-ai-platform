# AI 费用账本：P1 查询 RAG 接入与验证

日期：2026-09-10。

本轮完成查询向量化和重排接入。至此 P1 的文本、ASR、DashScope 视频、RAG Embedding、RAG Rerank 均已接入。P2 的费用查询接口、详情页和部署验收仍待完成；目前运行中的服务尚未切换到这些修改。

## 归属和入口

`VideoAnalysisService` 将执行代次传入 `RagOrchestrator.buildPrompt(task, executionNo)`；编排器根据真实任务 ID 创建 RAG_EMBEDDING 上下文，经检索服务传递到 Embedding 请求。调用重排时使用相同任务 ID、代次和子编号，阶段改为 RAG_RERANK。

每局仅在准备片段指导信息时检索一次，两个 RAG 阶段的子编号均为 0；这不是视频片段 0，而是该阶段的第一个查询。复用已冻结指导信息时不重新检索，因此不会重复记费。

- 在线视频调用必须显式携带上下文，缺失或阶段不匹配会报错。
- 原有无上下文检索、embedDocument 和离线评测入口不归入视频账本。
- Embedding 接口的带上下文方法不默认回退到离线接口，防止新 Provider 静默漏账。
- 没有候选、不启用重排或 RAG 被关闭时，不创建未发生调用的账本行。

## 费用写入

DashScope 和 OpenAI 兼容 Embedding 客户端均接入查询记账；实际价格仍按已配置模型的价格快照计算，未配置价格的模型保留未知费用。

请求准备完成后先登记，返回响应后先收尾记账，再验证向量或重排结果。Embedding/Rerank 按输入 Token 计价；优先使用 input_tokens/prompt_tokens 等输入字段，厂商仅返回 total_tokens 时采用该输入计量。这里不会套用到生成式文本/视频调用，不会把 total_tokens 一律当成输入 Token。

RAG HTTP 发送统一使用受控 OkHttp 配置和上一轮的 OneShotJsonBody，禁止隐式重试和重定向；响应大小限制为 1MiB。接口地址与请求载荷沿用原配置，使用执行预算限制请求时间。错误消息不再包含厂商原始响应、请求正文或完整网络异常。

未新增费用调度器、模型执行器或父任务费用缓存。直接沿用 AiCallRecorder、价格计算器和同一张账本。

## 异常与降级

- 登记失败：不发送请求；是否继续视频分析沿用已有 RAG fail-open 配置。
- HTTP 失败：有用量则记失败费用，无用量则保留未知，不默认为免费。
- HTTP 成功但向量/重排结果无效：保留成功回执用量，业务层报错或降级。
- 收尾写入暂不可用：沿用 Recorder 的有限写入重试，已有结果继续使用，不重新调用模型。
- 重排失败且允许降级：退回向量检索，已发生的重排调用仍在账本中。
- 请求发送前确认取消：NOT_SENT；网络中断则保留未知用量，中断标志不主动清除。

费用账本中的调用成功不等于 RAG 检索质量达标，也不等于视频任务最终成功。

## 验证

1. 两个 Embedding Provider 参数化测试：在线归属、离线不记视频费用、响应无效仍保留用量、登记失败零请求、失败用量及收尾失败不重调。
2. Rerank 测试：空候选零调用、结果无效仍保留用量、登记失败零请求、503 有用量不漏计；原有批量协议测试保留。
3. 编排测试：真实任务 ID 与执行代次传入检索，两类调用阶段分别正确；重排失败仍按原配置降级。
4. 本地 HTTP + 隔离 MySQL：两个视频并发完成查询向量化和重排，产生四条记录；任务、代次、阶段与输入计量正确。

模拟用量：每条查询向量化 1000 输入 Token，重排 2000 输入 Token，分别按 P0 快照计算为 0.0005 元、0.001 元，每个视频合计 0.0015 元。仅为模拟验收，不是付费调用或性能数据。

回归命令：

```powershell
mvn test '-Dcost.mysql.acceptance=true' -q
```

结果：本轮 Surefire 报告共 210 项，192 项通过、18 项条件跳过、0 失败、0 错误；已排除旧构建遗留报告。包含 8 项 Embedding 参数化测试、5 项 Rerank 测试、在线归属/降级测试和本地 HTTP + MySQL 并发测试。收尾精简兼容 Embedding 的无用参数后，额外重跑 8 项 Embedding 测试通过。

日志：`logs/ai-cost-p1-rag-regression.log`、`logs/ai-cost-p1-rag-embedding-test.log`。本轮不调用付费模型，只创建和删除随机 MySQL 验收库，不迁移业务库、不重启服务。
