# 线程池模拟压测（2026-09-08）

## 范围

直接调用生产 SegmentAnalysisExecutor，模拟AI使用30～60ms可中断等待。3个并发父任务，每个40个片段。默认不运行，通过 segment.load=true 显式启用。未访问云端AI、数据库、OSS，也未修改正在运行的服务。

本轮是线程池编排与承压验证，不是生产容量结论。等待时间从父任务开始到片段进入工作线程计算，包含提交等待和队列等待，不包含进入线程后的请求限速等待。队列峰值每2ms采样，可能遗漏瞬时峰值。

## 结论

- 120个片段在1/2/4线程下全部完成，无重复执行，并发数未超过配置。
- 4线程、队列16与128吞吐接近。大队列减少提交等待，但不提升处理能力；本轮不同父任务完成时间差异明显，不具备任务级公平保证。
- 12个模拟片段失败，108个成功；3个父任务均报告失败且确认子任务退出，成功回调保留。
- 180ms整局期限场景约182ms结束，3个父任务收敛，队列和活跃调用归零；短暂观察未发现迟到模拟写入。这里的模拟调用会响应中断，不代表真实HTTP调用一定立即退出。
- 保留1000ms请求间隔时，6个短调用耗时约5秒，最小启动间隔1000ms。1.19片段/s是短批次首个请求无需等待造成的边界效应，不代表突破限速。
- 本轮保持生产参数4线程/队列16/请求间隔1000ms，不凭短耗时模拟调大队列。
