# AI 费用账本：P1 文本接入与验证

日期：2026-09-10。

本轮接入文本交战区间识别。P0 的表结构、价格快照与计算器保持不变；ASR、视频和查询 RAG 尚未接入，不能据此宣称整条链路费用已完整记录。

## 执行顺序

1. `TextScreeningService` 显式传递任务 ID、执行代次、TEXT_SCREEN 和批次号；复用已保存响应时不调用客户端。
2. `DashScopeTextClient` 完成请求校验后，生成调用 ID，使用短事务登记账本。登记失败不发送 HTTP。
3. 发送前再次检查取消。明确未发送的调用标为 NOT_SENT，费用为 0。
4. 发起一次 HTTP 请求，不自动重发。完整读取响应后提取 usage，记录调用结果，再把原始响应交给业务层保存、解析。
5. 即使交战区间格式错误或响应被截断为不合格的业务输出，已返回的 Token 仍计费。HTTP 错误响应携带 usage 时也记录；超时、缺失用量保留费用未知。
6. 收尾落账失败只重试数据库写入，不重新调用模型，也不丢弃已获得的响应。

这里只区分“HTTP 调用成功”和“业务解析成功”，账本 SUCCEEDED 不代表交战内容已经通过业务校验。

## 保持结构简洁

- 直接复用 AiCallRecorder，没有新增通用模型执行器、费用消息队列或补账调度器。
- Token 归一化仅读取 usage 内字段。兼容厂商命名，不累加 video_tokens 等子项，不把 total_tokens 猜成 input_tokens。
- 非整数、溢出、负数或不同别名数值冲突都标为非法用量，避免静默少计费。
- 删除不再使用的最终汇总调用方法，主链路仍只生成片段结果。旧配置快照中的汇总提示字段保留，本次不改变在途执行的配置指纹。
- 旧的显式付费文本测试改为必须使用真实 Recorder；单独启动账本设施，不启动视频任务调度器。

## 验证范围

Mock HTTP 验证：登记先于请求；登记失败零请求；HTTP 429 携带用量；格式不合格但有 usage；网络超时；登记后取消；收尾失败不重调模型。

隔离 MySQL 与 Mock HTTP 联合验证：两个任务并发，每个任务各一条账本行；任务、执行代次、批次归属正确；RUNNING 行在 HTTP 请求前已提交；返回用量按价格快照算出金额。

模拟用量为输入 1000、输出 100 Token，测试价格取 P0 的 qwen3.8-flash 配置，预期每条为 0.0010700000 元。这是测试数据，不是真实付费调用或性能压测结果。

```powershell

```

只创建并删除随机验收库，不迁移业务库、不重启已部署服务，不调用付费模型接口。
