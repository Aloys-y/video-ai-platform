# AI 费用账本：P1 ASR 接入与验证

日期：2026-09-10。

本轮完成文件转写的费用接入。文本粗筛上一轮已完成；视频分析、查询 RAG 和费用展示仍待接入。本次没有更换模型、没有付费外部调用，没有迁移业务库或重启服务。

## 调用过程

1. 音轨编排显式传递任务 ID、执行代次、ASR 阶段与音轨编号。
2. ASR 客户端完成参数、凭据与请求校验后，短事务登记账本，再发送提交请求。登记失败不发送。
3. 云端接受提交后，绑定远端任务 ID 和提交 request ID，账本保留 RUNNING；接受提交不等于转写完成。
4. 查询前按当前任务、音轨编号和远端任务 ID 查找原始调用，只允许当前或更早代次。轮询不创建账本行。
5. 返回终态时，先将 usage.duration 的秒数写入原账本，再验证转写结果结构与下载地址。重复轮询幂等收尾，不累加收费。
6. 本地下载转写 JSON 不另记模型调用。业务解析失败不抹掉远端已经产生的费用。

复用上一轮远端任务时，费用继续归属于最初提交的执行代次。查询响应每次可能有不同 request ID，因此只保留最初提交的 request ID，不以轮询 ID 覆盖它。

## 失败边界

- 提交前明确取消：NOT_SENT，费用为 0。
- 提交收到失败回执且携带 duration：记录失败和已知用量，不默认免费。
- 提交超时、响应缺失有效远端 ID：保留未知状态，不自动重复提交。
- 已接受提交但查询失败或等待超时：保留原记录和远端 ID，不认定远端任务已取消。
- 远端终态 FAILED/CANCELED：记录 FAILED；有用量则计费，缺失则未知。
- 远端终态 SUCCEEDED 但子任务结果不合格：记录远端用量，业务层继续报错；费用账本的成功不代表转写业务通过校验。
- 收尾写库失败：沿用 Recorder 的有限写入重试，不重交 ASR。
- 找不到原始账本或出现歧义：明确报错，不静默丢账、不补造零费用记录。

未增加 ASR 轮询费用表、消息队列、恢复调度器。远端 ID 绑定失败或进程中断造成的待核对记录，仍按已有方案人工核对，不承诺自动补账。

## 验证

Mock HTTP 验证认证信息不会随结果下载泄漏、提交登记与绑定、错误回执用量、登记失败零请求、缺失原账本拒绝查询、终态先记费后业务校验、发送前取消。

隔离 MySQL + Mock HTTP 验证：一次提交、三次轮询（包含后续代次继续查询），最终始终一条记录，提交 request ID 不变，费用归原始代次；其他任务或其他音轨不能关联这条记录。

模拟厂商回执为 393 秒，使用 P0 的 qwen-audio-3.0-asr-flash-filetrans 标价快照，预期费用 0.0864600000 元。这是模拟测试数据，不是新增的付费调用。
