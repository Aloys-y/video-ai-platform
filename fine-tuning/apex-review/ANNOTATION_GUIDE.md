# APEX 对局复盘标注规范

## 标注目标

模型学习的是“如何依据画面复盘”，不是背诵赛季数值。每条结论都应能回指到片段中的视觉证据；武器伤害、英雄技能数值、地图轮换等可能变化的知识不进入训练答案，运行时由 RAG 补充。

## 片段选择

- 单条建议 15–60 秒，最长不超过 180 秒。
- 优先截取完整决策链：获得信息 → 做出选择 → 执行动作 → 产生结果。
- 覆盖交战、转点、资源管理、技能使用、团队协同和撤退，不要只收高光击杀。
- 同一场对局可切多条，但数据集划分必须按 `source_match_id` 分组，不能让同一局同时出现在训练集和测试集。

## 证据原则

- 只写画面或音画上下文能够确认的事实。
- 无法辨认英雄、枪械、敌方数量或队友意图时，写入 `uncertainties`，不要猜。
- `events.start_sec/end_sec` 相对当前片段起点计时。
- `reviews.evidence` 必须含时间点或明确画面动作；禁止只写“意识不好”“枪法一般”。
- `suggestion` 要可执行，例如“首次破甲后先回掩体换弹，再从右侧重新拉角度”，不要写“提高意识”。

## 严重程度

- `1`：轻微优化，不改变主要结果。
- `2`：明显影响换血、资源或队形。
- `3`：直接导致倒地、团灭或丢失关键机会。

## 类别边界

- `aim`：准星、预瞄、跟枪、压枪、射击节奏。
- `positioning`：高低差、交叉火力、暴露角度、可撤退空间。
- `cover`：掩体利用、peek 节奏、换弹/打药时的遮挡。
- `movement`：滑铲、攀爬、身法及交战中的移动路线。
- `resource`：弹药、甲、治疗、换甲、投掷物。
- `ability`：英雄技能/大招的时机和收益；不确定英雄时不要硬标具体技能。
- `information`：标记、脚步、击杀信息、敌我人数与视野处理。
- `rotation`：进圈、转点、路线与第三方风险。
- `teamfight`：集火、补枪、拉人、队形和交换。
- `decision`：接战、撤退、追击、切换目标等综合决策。

## 质量门槛

正式样本须经过第二人复核。复核人检查：视觉事实、时间点、类别、严重程度、建议可执行性，以及是否夹带无法从画面确认的版本知识。
