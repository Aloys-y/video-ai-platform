Linux/远端执行时改成客户端可访问的 SQL 绝对路径。此迁移只执行一次，DDL 非事务；中断后先检查已完成语句，再补未完成部分，不盲目重复 ALTER。先备份，确认 `analysis_task.task_id` 的字符集/排序规则与新增表一致（仓库默认 utf8mb4_unicode_ci），否则先调整新增表 DDL 与现库一致。

应用回退可保留新增列和表，旧代码不读取它们。不要用删除表方式回退已有分析数据。

## 使用约定

- 当前执行仍是 `analysis_task.retry_count`。用 `(task_id, retry_count)` 查询 `analysis_execution`，获取配置、ASR ID、转写/筛选/片段清单引用，避免在任务表复制同一份配置。
- `AnalysisExecutionMapper.insert` 只为当前 PROCESSING 执行建立快照。配置 JSON 应规范化，完整覆盖模型/提示词/媒体与筛选参数；`config_hash/input_hash` 均为 SHA256。输入摘要基于视频内容，不是签名 URL。相同哈希的复用还会比较完整配置快照。
- `bindOnce` 的 ASR ID/各清单引用只能写一次；重复绑定返回 0，调用方读取比对原值，同值视为已保存，异值报冲突。对象键应含任务/代次/产物摘要，后续 StorageService 写入方不得覆盖同键内容；数据库只保证引用不可改，不保证 OSS 内容不可改。
- 片段唯一键是 `(task_id, execution_no, segment_no)`。重复插入抛唯一键异常，由调用方读取并校验原记录，不能把冲突忽略后当新任务执行。保存顺序为完整素材清单冻结、插入 PREPARED、进入线程池前标记 PROCESSING、保存终态。
- `reuseSucceeded` 只复用同任务更早代次、相同输入/配置/时间范围的成功片段；记录来源，本次用量留空防止重复计费。调用方还须验证源对象存在、权限与版本兼容。配置变动时保守地重新分析。
- 当前代次和 PROCESSING 条件保护写入；迟到/取消后的结果写入返回 0，不可推动父任务完成。需要统计迟到远端费用时另记调用日志。重试仅清空当前步骤，旧执行和片段不删除。
- DTO 使用原视频毫秒坐标，片段序号从 0 开始，区间为 `[startMs,endMs)`。句段 ID 对同一转写稳定。引用存在性、原片时长边界和整份清单冻结由 P2/P3 的服务校验；P1 不提供任务扫描、领取或调度功能。
